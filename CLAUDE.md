# Directives for Claude (Project: Popcorn — shared watchlist + Stremio addon)

A private, self-hosted app for a small group (members add themselves in the UI): a shared movie & series watchlist with
TMDB metadata, plus a Stremio catalog addon served by the same server. Access is a
secret URL token, no accounts. Follow the rules below for all code suggestions.

## 💬 Response style

- Lead with the answer or next action. No preamble.
- Number multi-step instructions.
- Max 3–5 sentences unless I ask for detail.
- No restating my question, no summaries of what you just did.
- Don't mention what you didn't do or what code doesn't do.
- No hedging or filler ("Great question", "I hope this helps").
- If unsure, say so in one line and ask one question.

## 🏗️ Tech Stack

- **Server** (`src/server/`): Hono on Node (`@hono/node-server`), zod validation via `@hono/zod-validator`, Pino logging.
- **Web** (`src/web/`): Vite + React SPA, React Router, TanStack Query, Hono RPC client (`hc<AppType>`).
- **Language**: Strict TypeScript everywhere.
- **Database**: SQLite (`better-sqlite3`) via Drizzle ORM. Schema in `src/server/db/schema.ts`, migrations in `drizzle/` generated by `drizzle-kit`, applied automatically at server start.
- **Metadata**: TMDB API, server-side only (`src/server/tmdb.ts`).
- **UI**: Tailwind CSS v4, Shadcn UI (`src/web/components/ui/`), `cn` utility (clsx + tailwind-merge), lucide icons.

## 📝 Development Rules

### 1. Server / Web separation

- `src/web/` never imports runtime code from `src/server/`. Only `import type` (e.g. `AppType` for `hc`), so no server code or secrets reach the bundle.
- No secrets in `VITE_*` variables. The UI gets the config it needs from `GET /api/config`.
- Shared constants (enums like `status`, `type`) go in `src/shared/` and must be safe to ship to the browser.

### 2. API and data

- All API routes live in `src/server/routes/` and are chained on the Hono app so `AppType` stays accurate for the RPC client.
- Validate every input with `zValidator` (types, lengths, enums). Return proper status codes (400, 404, 409) with a small JSON `{ error }`.
- Web data fetching and mutations go through TanStack Query hooks in `src/web/lib/api.ts`. Invalidate the affected queries after a mutation.
- DB access through Drizzle's query builder only; no `sql.raw` with input.
- Store TMDB metadata at add time. Don't call TMDB per render or per list item.

### 3. Access (secret URL token)

- Everything is mounted under `/:token`, behind the single gate middleware in `src/server/token.ts` (constant-time compare), except the MCP OAuth routes listed below. Any other path returns a bare 404.
- Never add a route outside the gated sub-app. The only exception is this fixed list, mounted from `src/server/routes/oauth.ts` before the gate: `/mcp`, `/oauth/authorize`, `/oauth/register`, `/oauth/token`, `/oauth/revoke`, `/.well-known/oauth-protected-resource`, `/.well-known/oauth-protected-resource/mcp`, `/.well-known/oauth-authorization-server`. Adding to this list needs my explicit approval.
- `/mcp` requires a valid OAuth access token, and those tokens reach `/mcp` only, never the gated app. Only hashes of OAuth codes and tokens are stored.
- `MCP_CONNECT_CODE` is accepted only by the consent form at `POST /oauth/authorize`, rate limited and compared through `src/server/token.ts`. `APP_TOKEN` is never accepted by any OAuth route. Never log the form body.
- Never commit the real hostname, the token or any secret. Committed files use `${SITE_URL}` / `popcorn.<domain>`; real values live only in the gitignored `mise.toml` and the Portainer stack env.
- Never log the token. Send `Referrer-Policy: no-referrer` on every response, since the token is in the URL. External links use `rel="noreferrer"`.

### 4. Stremio addon

- `src/server/routes/stremio.ts`: `manifest.json` and `catalog/:type/:id.json`. No `stremio-addon-sdk`.
- We only implement the `catalog` resource with IMDb ids (`tt…`). Cinemeta provides meta and other addons provide streams. Titles without an `imdb_id` are excluded from catalogs.
- Hidden (surprise) titles appear only in the random catalogs and are excluded from all the others.
- Stremio responses send `Access-Control-Allow-Origin: *` (Stremio routes only) and a short `Cache-Control`.
- Bump the manifest `version` when catalogs or manifest fields change. Never change the manifest `id`.

### MCP

MCP tools never return, change or create a hidden title. All tool handlers go through `run()`.

Connecting (needs `MCP_CONNECT_CODE` set on the server; the sign-in page asks for it, then which member you are):

- Claude Code: `claude mcp add --scope user --transport http popcorn ${SITE_URL}/mcp`, then `/mcp` > Authenticate.
- claude.ai: Settings > Connectors > Add custom connector, `https://popcorn.<domain>/mcp`, then sign in.
- Gemini CLI: `{ "mcpServers": { "popcorn": { "httpUrl": "https://popcorn.<domain>/mcp" } } }` in `~/.gemini/settings.json`, then `/mcp auth popcorn`.
- Revoking: `curl -s ${SITE_URL}/<token>/api/connections` lists connections, `curl -s -X DELETE ${SITE_URL}/<token>/api/connections/<id>` removes one. Rotating `MCP_CONNECT_CODE` disconnects all of them.

### 5. PWA

- `vite-plugin-pwa` generates the manifest and service worker. Both are served under `/<token>/` with relative `start_url`/`scope`, so the installed app keeps the token and the SW controls nothing outside it.
- The SW precaches the app shell, uses network-first for `GET /api/titles`, `/api/members` and `/api/config`, and cache-first for TMDB posters. It never caches `/api/search`, non-GET requests or `/stremio/*`.
- Offline is read-only: disable mutations and show the offline notice.

### 6. Logging (Debugging)

- Do not use `console.log()`. On the server, use **Pino** via `src/server/logger.ts`, with a child logger per handler / function:

  ```typescript
  import { logger } from '@server/logger';
  const contextLogger = logger.child({ function: 'addTitle', tmdbId });
  contextLogger.info("Title added");
  ```

## 🧰 Tooling & Environment

- Tool versions (Node, pnpm) and environment variables are managed with **mise**. Do not suggest nvm, direnv, or manually exporting env vars; use `mise.toml` / `mise` commands. `mise.toml` is gitignored; `mise.toml.example` is the committed template.
- Env vars: `APP_TOKEN`, `MCP_CONNECT_CODE` (optional; MCP sign-in stays disabled without it), `TMDB_API_TOKEN` (TMDB v4 read access token), `SITE_URL`, `DATABASE_PATH` (default `/data/popcorn.db`), `PORT`.
- Scripts: `pnpm dev` (server + Vite together), `pnpm build`, `pnpm start`, `pnpm typecheck`, `pnpm lint`, `pnpm db:generate`.

## 🐳 Docker Build & Deploy

- **The image is built by GitHub Actions, never locally.** Every push to `main` runs `.github/workflows/ci.yml`: typecheck + lint + build, then pushes `ghcr.io/baptistebergmann/popcorn` tagged `latest` and the short SHA (amd64 only). `git push origin main` *is* the build step. Do not run `docker build`/`buildx` to ship a change.
- Base image is `node:22-bookworm-slim` (glibc, so `better-sqlite3` prebuilt binaries work). Don't switch to alpine.
- All app config is runtime env vars on the container, not build args.
- Deploying = push to `main`, wait for CI to go green (`gh run watch`), then `mise run portainer_redeploy` to make the Portainer stack (`docker-compose.portainer.yml`, `pull_policy: always`) re-pull `:latest`. Portainer pulls the image; it does not build from source.
- The SQLite DB lives on the `popcorn-data` volume at `/data`. Never recreate or prune that volume.
- Public access goes through a Cloudflare Tunnel public hostname pointing at the container port.

## ✅ Git Workflow

- Follow [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/) for every commit message: `<type>[optional scope]: <description>`, e.g. `feat(stremio): add watched catalog`. Common types: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`. Use `!` (or a `BREAKING CHANGE:` footer) for breaking changes.
- Commit as soon as each subtask/fix in a multi-step task is done and verified (e.g. typechecks pass). Don't batch unrelated fixes into one commit. Keep each commit small and scoped to one subtask.
- After every commit, immediately update `CHANGELOG.md` in a follow-up commit: add a `` `<short-hash>` <subject> `` line under the `## <YYYY-MM-DD>` heading for that day (newest entry at the top of its date group; add a new date heading at the top of the file if the commit is the first of a new day).
