# Popcorn — shared watchlist + Stremio addon (MVP)

Status: draft — needs design
Approved by:

## Goal
A tiny private web app where the two of us add movies and TV series to a shared
watchlist, with metadata pulled from TMDB. The same server exposes a Stremio
catalog addon so the list shows up as rows on the Stremio home screen on every
device.

## Out of scope
- Accounts / login. Access is a secret URL only (see Access and security).
- Streams. The addon only provides catalogs; playback comes from whatever stream
  addons are already installed in Stremio.
- "Pick a random movie tonight", genre/runtime sorting and filters, per-person
  ratings. Later plans.
- i18n. UI copy is French only, hardcoded (no i18n library).
- Offline edits / background sync.
- Push notifications.
- Multi-arch images. The Proxmox host is amd64.

## Current state
Empty repo: only `CLAUDE.md`, `.claude/agents/`, `.gitignore` and this plan.

## Approach
One pnpm package, one Docker container, two halves:
- **Server** (`src/server/`): Hono on Node (`@hono/node-server`). It serves the JSON
  API, the Stremio routes and the built frontend. Validation with zod
  (`@hono/zod-validator`), logging with Pino.
- **Web** (`src/web/`): a Vite + React + TypeScript SPA with Tailwind v4 + Shadcn,
  React Router for the two pages, TanStack Query for fetching and mutations, and
  Hono's typed RPC client (`hc<AppType>`) so the API types come straight from the
  server routes (type-only import, no runtime server code in the bundle).
- **Storage**: SQLite file on a Docker volume (`/data/popcorn.db`) via `better-sqlite3`
  + Drizzle ORM. Migrations generated by `drizzle-kit` and applied automatically at
  server start (single container, single writer, so this is safe).
- **Metadata**: TMDB API v3 called server-side only, with a v4 read access token
  in `TMDB_API_TOKEN`. On add, fetch details + `external_ids` to get the IMDb id.
- **Stremio addon**: plain Hono routes returning JSON (no `stremio-addon-sdk`; it
  brings its own Express server and we only need two endpoints).

Alternative considered: Next.js (same as lepetitmonde). It's heavier (image, RAM,
build time), and Server Actions complicate a secret-path token, since every action
needs its own check. One Hono middleware gates everything here.

### Why IMDb ids matter
Stremio identifies titles by IMDb id (`tt1234567`). If our catalog returns those,
Stremio's built-in Cinemeta addon provides the detail page (cast, episodes...) and
the existing stream addons resolve playback. We only implement `catalog`.
Titles TMDB has no IMDb id for are saved and shown in the web UI with a "not in
Stremio" badge, and left out of the addon's catalogs.

## Data and migrations
Table `titles`:
| column | type | notes |
|---|---|---|
| id | integer pk | |
| tmdb_id | integer | |
| type | text | `movie` \| `series` (TMDB `tv` maps to `series`, Stremio's name) |
| imdb_id | text null | `tt…` from TMDB external_ids |
| title | text | |
| year | integer null | |
| poster_path | text null | TMDB path; full URL built when serving |
| overview | text null | |
| genres | text | JSON array of names |
| runtime | integer null | minutes (movies), avg episode runtime (series) |
| added_by | text null | one of `MEMBERS`, chosen in the UI and remembered in localStorage |
| status | text | `to_watch` \| `watched`, default `to_watch` |
| added_at | integer | unix ms |
| watched_at | integer null | unix ms |

Unique index on `(tmdb_id, type)`: adding the same title twice returns 409 and the
UI shows "already in the list".

## Access and security
- `APP_TOKEN` env var: a long random string (`openssl rand -hex 24`). Everything is
  mounted on a sub-app under `/:token`, behind one middleware that compares the
  segment with `APP_TOKEN` in constant time (`crypto.timingSafeEqual`). Anything else,
  including `/`, returns a bare **404** (not 401, so nothing reveals the app is there).
- `TMDB_API_TOKEN` and `APP_TOKEN` live only in `src/server/`. The web bundle
  imports server code with `import type` only, and there are no secret `VITE_*` vars.
- Input validation (zod): search query ≤ 100 chars; `tmdbId` a positive int;
  `type` and `status` from the allowed enums; `addedBy` one of `MEMBERS`. TMDB URLs
  are built only from validated values.
- `Referrer-Policy: no-referrer` on every response, since the token is in the URL
  and poster requests to TMDB would otherwise leak it. Outbound links get `rel="noreferrer"`.
- CORS `Access-Control-Allow-Origin: *` on the Stremio routes only (Stremio requires it).
- `X-Robots-Tag: noindex`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`
  (Hono `secureHeaders` middleware).
- Known limits of a secret-URL scheme: anyone who gets the link can edit the list,
  and the token appears in Cloudflare logs and in Stremio's addon list. Fine for
  two people. Cloudflare Access could be added later for the web UI only (Stremio
  can't log in through it).

## Routes
All under `/<token>`:
| Path | What |
|---|---|
| `GET /` , `GET /add` | SPA (`index.html`); `/assets/*` static files |
| `GET /api/titles?status=` | List, newest first |
| `POST /api/titles` `{ tmdbId, type, addedBy }` | Fetch TMDB details, insert |
| `PATCH /api/titles/:id` `{ status }` | Mark watched / to watch |
| `DELETE /api/titles/:id` | Remove |
| `GET /api/search?q=` | TMDB `/search/multi`, movies + tv only, each flagged `inList` |
| `GET /api/config` | `{ members, stremioManifestUrl }` for the UI |
| `GET /stremio/manifest.json` | Stremio manifest |
| `GET /stremio/catalog/:type/:id.json` | Catalog feed |

SPA under a token path: Vite builds with `base: './'`, and the server injects
`<base href="/<token>/">` into `index.html` when serving it so assets resolve on
any route. React Router uses `basename` = the first path segment.

Stremio resolves catalog URLs relative to the manifest, so the addon base is
`/<token>/stremio/`. Install link shown in the UI:
`stremio://<host>/<token>/stremio/manifest.json` (plus the https URL to copy).

Manifest:
```json
{
  "id": "local.popcorn.watchlist",
  "version": "1.0.0",
  "name": "Popcorn",
  "description": "La liste de films et séries de Alex & Sam",
  "resources": ["catalog"],
  "types": ["movie", "series"],
  "idPrefixes": ["tt"],
  "catalogs": [
    { "type": "movie",  "id": "to_watch", "name": "Popcorn · À voir" },
    { "type": "series", "id": "to_watch", "name": "Popcorn · À voir" },
    { "type": "movie",  "id": "watched",  "name": "Popcorn · Déjà vus" },
    { "type": "series", "id": "watched",  "name": "Popcorn · Déjà vus" }
  ]
}
```
Catalog response: `{ "metas": [{ "id": "tt…", "type", "name", "poster", "releaseInfo", "description" }] }`,
newest first, only rows with an `imdb_id`, posters as `https://image.tmdb.org/t/p/w342…`.
Unknown type/id → 404. `Cache-Control: max-age=60` so changes show up quickly and
Cloudflare doesn't hold stale lists.

## PWA
Installable on phones (Android + iOS "Sur l'écran d'accueil"), since that's the
main way we'll use it.
- `vite-plugin-pwa` (Workbox, `generateSW`, `registerType: 'autoUpdate'`) generates
  the web manifest and service worker at build time. Icons generated once from a
  source SVG with `@vite-pwa/assets-generator` and committed to `src/web/public/`.
- **Token-scoped**: manifest and service worker are served under `/<token>/`,
  with relative `start_url: "./"` and `scope: "./"`, so the installed app opens
  `/<token>/` and the SW only controls that path. Installing from the token URL
  is enough; nothing else to configure on the phone.
- Manifest: `name: "Popcorn"`, `lang: "fr"`, `display: "standalone"`, theme and
  background colors from the design tokens, 192/512 icons + maskable, plus
  `apple-touch-icon` and `apple-mobile-web-app-*` meta tags in `index.html` for iOS.
- Caching:
  - App shell (JS/CSS/HTML/icons): precached.
  - `GET /api/titles`, `/api/config`: network-first, short fallback cache, so the
    list still opens offline (read-only).
  - TMDB poster images (`image.tmdb.org`): cache-first, capped (~300 entries, 30 days).
  - Never cached: `/api/search`, any non-GET, `/stremio/*`.
- Offline: mutations are disabled with a "Hors ligne" notice. No background sync
  in the MVP.
- The SW must not cache the bare 404 returned for wrong tokens, and must never
  be registered outside `/<token>/`.

## Dev workflow
- `pnpm dev`: runs `tsx watch src/server/index.ts` (port 8787) and `vite` (port 5173)
  together (`concurrently`). Vite proxies `/<token>/api` and `/<token>/stremio` to
  the server, so the dev URL is `http://localhost:5173/<token>/`.
- `pnpm build`: `vite build` → `dist/web`, `tsc -p tsconfig.server.json` (or
  `tsup`) → `dist/server`. `pnpm start`: `node dist/server/index.js`.
- `pnpm typecheck`, `pnpm lint` (ESLint flat config), `pnpm db:generate` (drizzle-kit).

## Steps
1. Scaffold: pnpm package, TS strict (`tsconfig` for web + server), Vite + React,
   Tailwind v4 + Shadcn init, ESLint, `mise.toml.example` (node, pnpm, env),
   `CHANGELOG.md`. Files: root config, `src/web/` skeleton.
2. Server skeleton: env, logger, Hono app with token gate + secure headers + 404,
   static/SPA serving with `<base>` injection, `/api/config`. Files: `src/server/*`.
3. Database: Drizzle schema, first migration, connection that migrates on
   startup. Files: `src/server/db/*`, `drizzle/`, `drizzle.config.ts`.
4. TMDB client: `searchMulti(query)`, `getDetails(type, tmdbId)` including
   external_ids, mapped to our row shape. Files: `src/server/tmdb.ts`.
5. API routes: titles CRUD + search, exported `AppType`. Files: `src/server/routes/api.ts`.
6. Stremio routes + CORS. Files: `src/server/routes/stremio.ts`.
7. UI: `hc` client + query hooks, list page, add/search page, name picker
   (localStorage), install-addon card. Files: `src/web/*`.
8. PWA: `vite-plugin-pwa` config, icons, iOS meta tags, offline notice; server
   serves `manifest.webmanifest` and `sw.js` under the token with
   `Cache-Control: no-cache` on the SW. Files: `vite.config.ts`, `src/web/public/`,
   `src/web/index.html`, `src/server/app.ts`.
9. Docker + CI + deploy: multi-stage `Dockerfile` on `node:22-bookworm-slim`
   (glibc, so `better-sqlite3` prebuilt binaries work), prod deps only, non-root,
   `/data` volume; `.dockerignore`; `.github/workflows/ci.yml` (typecheck, lint,
   build, push `ghcr.io/baptistebergmann/popcorn:latest` + short SHA);
   `docker-compose.portainer.yml`; `mise run portainer_redeploy` task copied from
   lepetitmonde.

Each step is its own commit and leaves the app building.

## Deployment
- Portainer stack on the Proxmox host: the `app` service with `pull_policy: always`,
  volume `popcorn-data:/data`, env `APP_TOKEN`, `TMDB_API_TOKEN`, `SITE_URL`, `MEMBERS=Alex,Sam`,
  a small `mem_limit` (256 MB is plenty).
- Cloudflare Tunnel: add a public hostname (e.g. `movies.<domain>`) to the existing
  tunnel, pointing at `http://<host>:<port>`. If there's no tunnel on that host,
  add the `cloudflared` service from lepetitmonde's `docker-compose.cloudflared.yml`.
- Backups: the whole state is `/data/popcorn.db`. A periodic `sqlite3 .backup` copy can
  be a later plan.

## Design
To be completed by the designer subagent.

Behaviour the screens need:
- List: poster grid, title, year, type, who added it, "watched" toggle, remove
  (with confirm dialog), "not in Stremio" badge when `imdb_id` is null. Tabs
  "To watch" / "Watched", filter Movies / Series / All.
- Add: debounced search box, results with poster/year/type, an "Add" button
  that becomes "In list" when the title is already saved.
- Name picker: first visit asks "Who are you?" (one button per `MEMBERS` name),
  remembered on the device.
- Stremio card: install button (`stremio://` link) and copyable URL.
- TMDB attribution in the footer (required by their terms).
- PWA: app icon (popcorn), theme color, splash/background color, offline notice,
  and how the app looks in standalone mode (safe-area insets on iOS).
- UI copy in French. TMDB requests use `language=fr-FR` (titles, overviews,
  posters), falling back to the original title when there's no French one.
- Mobile first. Mostly used on phones, sometimes on a laptop.

## Risks and open questions
- **Domain/hostname** for the tunnel (e.g. `popcorn.<domain>`).
- Stremio caches catalogs on the client, so a newly added title may take a refresh
  of the home screen to appear.

## How to verify
1. `pnpm dev`, open `/<token>/`: empty state shows. Open `/` or `/wrong-token/`:
   bare 404.
2. Add a movie and a series from search; they appear in "To watch" with posters.
   Adding the same one again shows "already in the list".
3. `curl /<token>/stremio/manifest.json` and `/<token>/stremio/catalog/movie/to_watch.json`:
   valid JSON, CORS header present, only titles with `tt` ids.
4. Install the addon in Stremio desktop via the https URL: rows "Popcorn · À voir"
   appear, clicking a title opens its Cinemeta page.
5. Mark watched: it moves to "Popcorn · Déjà vus" in the UI and in Stremio after a refresh.
6. PWA: install on Android (Chrome) and iOS (Safari → Sur l'écran d'accueil); it
   opens on `/<token>/` standalone. Turn on airplane mode: the list still shows,
   add/remove are disabled. Lighthouse PWA check passes.
7. Negative: `curl -X DELETE /wrong-token/api/titles/1` → 404, DB unchanged.
   `grep` the built `dist/web` for the TMDB token → no match.
